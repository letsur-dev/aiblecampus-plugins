# 설정과 비밀값

## 분류

| 종류 | 예시 | 전달 방법 |
| --- | --- | --- |
| 일반 설정 | 기능 플래그, 공개 기준 URL, 로그 수준 | `env` |
| 비밀값 | API 키, 비밀번호, database Credential | `secrets` |
| 플랫폼 관리 값 | `PORT`, `DATABASE_URL`, `PAAS_DEPLOYMENT_ID`, `PAAS_STORAGE_URL`, `PAAS_STORAGE_TOKEN` | 직접 설정하지 않음 |

비밀처럼 보이는 값은 일반 설정으로 넣지 않는다. 사용자에게 분류가 불분명한 값을 받으면 비밀값으로 취급한다.

## 검증과 배포

- `validate_project`에는 일반 설정 값과 `secretKeys`만 전달한다.
- 비밀값 원문은 검증 요청에 전달하지 않는다.
- `deploy_project`에만 필요한 비밀값을 `secrets`로 전달한다.
- 비밀값을 답변, 로그, 소스 파일과 커밋에 기록하지 않는다.
- 사용자가 준 값을 확인 목적으로 되읽지 않는다.

## 저장된 설정 관리

- `deployment_config`는 일반 설정 값과 비밀값 키 이름만 반환한다.
- `set_deployment_config`의 문자열 값은 추가 또는 교체다.
- `null`은 해당 키 삭제다.
- 한 키를 `env`와 `secrets`에 동시에 넣지 않는다.
- 플랫폼 관리 값은 조회만 하고 추가, 변경하거나 삭제하지 않는다.
- 설정 변경은 실행 중인 앱을 즉시 바꾸지 않는다. 같은 배포를 다시 배포한 다음 revision부터 적용된다.
- 비밀값을 교체한 뒤에는 새 revision이 정상 실행되는지 확인한다.

## 오류 처리

- 필수 키가 없으면 사용자에게 서비스 이름과 필요한 키 이름만 설명한다.
- 비밀값 형식이 잘못돼도 원문 전체를 오류 메시지에 포함하지 않는다.
- Credential이 폐기됐거나 권한이 없으면 사용자가 해당 서비스에서 새 값을 발급해야 한다고 설명한다.
