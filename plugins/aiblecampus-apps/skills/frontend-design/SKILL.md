# 프런트엔드 디자인

Anthropic 원본을 에이블캠퍼스에 맞게 연결한 스킬이다. 먼저 [원본 디자인 지침](references/upstream.md)을 읽고 적용한다. 아래 규칙은 기존 제품 작업과 배포 경계를 보완한다.

## 공통 실행 규칙

- 사용자에게 보여 주는 설명, 진행 상황과 최종 응답은 한국어로 작성한다. 코드, 기술 식별자와 URL은 원문을 유지한다.
- 브랜드 이름은 **에이블캠퍼스**, 제품 이름은 **에이블캠퍼스 Apps**로 표기한다.
- 개발이나 설명 요청은 배포 요청이 아니다. 명시적으로 배포를 요청한 경우에만 `../deploy-to-apps/SKILL.md`를 읽고 배포한다.
- 기존 프로젝트의 디자인 시스템, 저장소 규칙과 사용자의 범위를 우선한다. 요청과 무관한 전면 개편을 하지 않는다.

## 작업 흐름

1. 요청한 화면의 목적, 사용자, 실제 콘텐츠와 기존 컴포넌트 및 디자인 토큰을 확인한다. 대화나 코드에 있는 정보를 다시 질문하지 않는다. 필수 정보가 없을 때만 짧게 확인한다.
2. 새 디자인은 원본의 기획, 구현, 비평 순서를 적용한다. 기존 화면 수정은 기존 색상, 글꼴과 구조를 재사용하고 요청한 부분에 맞게 계획 규모를 줄인다.
3. 정상 상태뿐 아니라 로딩, 빈 화면, 오류와 로그인 상태를 구현한다. 모바일 레이아웃, 키보드 포커스, 대비와 reduced-motion을 확인한다.
4. 사용할 수 있는 브라우저나 프로젝트 검증 도구로 실제 동작을 확인한다. 화면 검증을 못 했다면 코드 검증과 구분하여 보고한다.
5. AI 요청과 응답 기능도 요청했다면 `../build-ai-feature/SKILL.md`를 함께 읽어 실제 연결을 구현한다. 디자인 요청만으로 API 키를 발급하거나 배포하지 않는다.

- 사용자가 지정한 스타일과 기존 제품의 공통 UI 규칙이 원본의 새로운 시각적 방향 제안보다 우선한다.
- 설명 자료만 필요한 경우에는 `../eli5/SKILL.md`를 사용한다. 두 스킬을 서로 반복 호출하지 않는다.
