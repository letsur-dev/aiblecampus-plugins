# 쉬운 시각적 설명

Anthropic 원본을 에이블캠퍼스에 맞게 연결한 스킬이다. 먼저 [원본 지침](references/upstream.md)을 읽는다. 아래 규칙은 언어, 작업 범위와 실행 방법을 보완한다.

## 공통 실행 규칙

- 사용자에게 보여 주는 설명, 진행 상황과 최종 응답은 한국어로 작성한다. 코드, 기술 식별자와 URL은 원문을 유지한다.
- 브랜드 이름은 **에이블캠퍼스**, 제품 이름은 **에이블캠퍼스 Apps**로 표기한다.
- 개발이나 설명 요청은 배포 요청이 아니다. 명시적으로 배포를 요청한 경우에만 `../deploy-to-apps/SKILL.md`를 읽고 배포한다.
- 기존 프로젝트의 디자인 시스템, 저장소 규칙과 사용자의 범위를 우선한다. 요청과 무관한 전면 개편을 하지 않는다.

## 설명 작성

1. 주제는 사용자의 요청과 현재 대화에서 파악한다. 원본의 `$ARGUMENTS`는 실제 주제로 대체한다. 사실관계와 모르는 부분을 구분한다.
2. 처음 접하는 성인도 이해하도록 쉬운 말과 구체적인 예를 사용한다. 어린아이에게 말하는 어투나 부정확한 비유는 피한다.
3. 큰 그림과 적은 글로 HTML 자료를 만든다. SVG, CSS 도형이나 간단한 상호작용으로 관계와 흐름을 보여 준다. 단계 번호는 실제 순서가 있을 때만 사용한다.
4. 모바일에서도 읽히는 글자 크기, 충분한 대비, 그림의 대체 설명과 키보드 접근성을 확인한다. 외부 서비스 없이 열 수 있는 단일 HTML을 우선한다.
5. 설명 자료는 기존 앱과 분리된 파일로 저장하고 링크나 지원되는 미리보기로 전달한다. 실제 확인한 범위만 보고한다.

- 일반적인 "쉽게 설명해줘"는 그림이 이해에 도움이 되는 개념 설명일 때 선택한다. 한 줄 답변으로 충분한 질문에는 HTML을 만들지 않는다.
- 설명만 요청한 경우 앱 코드를 수정하거나 배포하지 않는다.
