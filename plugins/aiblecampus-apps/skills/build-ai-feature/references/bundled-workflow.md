# 산출물 AI 기능 구현

AI 연결과 모델 문의에 답하고 사용자가 구현을 요청하면 웹앱에 실제 AI 기능을 구현한다. 사용자에게 전달하는 설명, 진행 상황과 최종 결과는 한국어로 작성한다. 기존 프레임워크와 화면을 유지하고 필요한 서버 기능을 추가한다.

## 공식 제품명

브랜드의 한국어 이름은 **에이블캠퍼스**, 이 제품의 공식 표기는 **에이블캠퍼스 Apps**다. 진행 설명, 최종 응답, 복사할 프롬프트, 새 세션용 인계문에서도 이 표기를 그대로 사용한다. 사용자의 입력이나 과거 대화에 오타가 있어도 제품명은 공식 표기로 바로잡는다. “아블캠퍼스”, “에이블캐퍼스”처럼 발음을 추정해 바꾸지 않는다. `aiblecampus-apps`, `.aiblecampus-deploy.json`, 도구 이름과 URL 등 기술 식별자는 원문을 유지한다.

## 연결 가능 여부와 모델 문의

- "에이블캠퍼스 플러그인으로 AI API 붙일 수 있어?", "무슨 모델 붙일 수 있어?", "API 키 필요해?"는 구현 전 문의로 처리한다. Apps는 Portal에 지정된 산출물용 환경과 Letsur AI Gateway를 연결하는 전용 도구를 제공한다고 설명한다.
- `get_ai_gateway`로 지정된 환경과 현재 모델 목록을 조회해 답한다. 기존 workspace가 있으면 유지하고 지정된 대상이 없으면 개인 workspace로 조회할 수 있다. 프로젝트 생성이나 배포 대상 선택을 먼저 요구하지 않는다.
- 지원 모델은 조회 결과를 기준으로 안내한다. 고정된 모델 목록이나 모든 provider 지원을 약속하지 않는다. 모델 목록에 있다는 사실과 요청한 API의 지원 여부를 구분한다. 목록만 확인했다면 실제 AI 응답까지 검증했다고 설명하지 않는다.
- API 키는 구현 시 `configure_ai_gateway`가 지정 환경에서 받아 프로젝트에 저장한다. 기본 연결 절차에서 사용자에게 개인 API 키나 Portal 접속 코드를 요구하지 않는다.
- 문의만으로 `configure_ai_gateway`, `verify_ai_gateway`, 파일 생성, 앱 수정이나 배포를 실행하지 않는다. 구현 요청이 이어지면 아래 환경 연결 절차로 진행한다.
- 도구가 보이지 않으면 사용 가능한 도구 검색과 `apps_plugin_status`로 현재 세션의 로드 상태를 확인한다. 확인할 수 없으면 그 제한을 설명하고 [플러그인 관리 지침](../manage-apps-plugin/SKILL.md)의 진단 절차를 따른다. 문의만으로 설치 변경이나 인증 초기화를 수행하지 않는다.
- 조회가 실패하면 로그인, 권한, 연결 또는 운영 환경 오류를 구분해 설명한다. 현재 모델 목록을 확인하지 못했다고 명시하고 "AI 연결 기능이 없다"거나 "외부 API 키를 직접 준비해야 한다"고 대체 안내하지 않는다.

## 환경 연결

1. 현재 프로젝트와 요청한 기능을 확인한다. 개인 또는 팀 배포 대상이 이미 지정됐다면 그 workspace를 유지한다. AI 개발만 요청했고 배포 대상이 없으면 개인 workspace로 환경을 조회할 수 있다. 이 조회를 이후 배포 대상을 사용자가 선택한 것으로 기록하지 않는다.
2. `get_ai_gateway`로 지정된 Portal 환경과 현재 모델 목록을 확인한다. 도구가 없으면 같은 플러그인의 [manage-apps-plugin](../manage-apps-plugin/SKILL.md)으로 도구 로드를 복구한다. 설치 여부만으로 현재 세션의 도구 인식을 단정하지 않는다. 로그인 정보가 없거나 만료됐으면 `start_apps_login`과 `complete_apps_login`으로 인증한 뒤 다시 확인한다. 운영 환경 오류를 로그인 반복으로 해결하려 하지 않는다.
3. [Gateway 구현 기준](references/gateway.md)을 읽는다. 모델 목록에 실제로 있는 모델 중 요청한 기능과 엔드포인트를 지원하는 모델을 선택한다. 목록에 있다는 이유만으로 모든 API를 지원한다고 가정하지 않는다. 사용자 지정 모델이 있으면 우선하고 없으면 해당 기능을 지원하는 일반 텍스트 모델을 선택한다.
4. `configure_ai_gateway`에 프로젝트 절대경로, 선택한 모델, 알고 있는 workspace를 전달한다. 이 도구가 운영자가 지정한 산출물 환경의 최신 키를 `.env.apps-ai`에 저장한다. 키나 Portal 접속 코드를 사용자에게 요청하거나 도구 결과, 명령어 인자와 대화에 출력하지 않는다. Claude나 Codex 자체의 게이트웨이 설정을 변경하지 않는다.

## 구현과 검증

- 브라우저는 산출물의 같은 출처 서버 경로를 호출한다. 서버만 `LETSUR_API_KEY`, `LETSUR_BASE_URL`, `LETSUR_MODEL`을 읽어 Gateway에 요청한다. 순수 HTML 앱이면 서버 경로를 추가한다. 브라우저 직접 호출이나 localStorage의 키 저장으로 대체하지 않는다.
- `.env.apps-ai`가 자동으로 로드된다고 가정하지 않는다. 로컬 Node 실행은 `node --env-file=.env.apps-ai server.mjs`처럼 명시적으로 읽고 기존 프레임워크에서는 시작 명령에 같은 설정을 연결한다. 운영에서는 Apps가 환경변수를 주입한다. 선택적 파일 로드가 필요한 실행 명령에는 Node 22.18 이상의 `--env-file-if-exists=.env.apps-ai`를 사용할 수 있다.
- 비밀 파일은 읽어 출력하지 않는다. `.env.apps-ai`가 Git에 이미 추적된 파일이면 먼저 추적에서 제외한다. `.gitignore`만으로 이미 추적된 파일이 제외되지는 않는다. 정적 자산 경로, 번들, Docker COPY, 에러 본문과 로그에 키가 포함되지 않게 확인한다. 정적 파일 서버는 명시한 public 디렉터리만 제공하고 프로젝트 전체를 공개하지 않는다.
- 요청 크기와 입력 길이, 응답 제한시간, 출력 토큰을 제한한다. 기존 사용자 인증과 사용 제한이 있다면 AI 경로에도 적용한다. 공개 체험용 앱도 요청 제한과 동시 요청 상한을 둔다. 모델, upstream URL, system 프롬프트를 브라우저 입력에 그대로 위임하지 않는다.
- 로딩, 완료, 취소와 실패 상태를 구분한다. 빈 응답과 잘린 응답도 처리한다. API 키, 프롬프트 원문과 인증 헤더를 로그에 남기지 않는다. 401, 402와 월 한도 초과를 무작정 재시도하지 않는다.
- `verify_ai_gateway`는 선택한 텍스트 모델에 짧은 Chat Completions 요청을 한 번 보내 실제 연결을 확인한다. 다른 API를 쓰는 기능은 그 엔드포인트를 산출물 서버에서 직접 검증한다. 연결 검증 성공을 앱 전체 검증 성공으로 보고하지 않는다.
- 산출물 서버를 실행하고 브라우저가 사용하는 것과 같은 경로로 실제 요청과 응답을 확인한다. 잘못된 입력, upstream 실패와 시간 초과도 모의 테스트한다. 테스트에서 모델 응답을 고정 문자열로 대체했다면 실제 AI 연결 검증 결과와 구분한다.

## 배포 경계와 설정 전달

AI 기능 개발 요청만 받았으면 구현과 로컬 검증에서 끝낸다. 배포하거나 기존 앱을 재시작하지 않는다. 사용자가 명시적으로 배포를 요청하면 [deploy-to-apps](../deploy-to-apps/SKILL.md)를 사용한다.

`validate_project`와 `deploy_project`에는 `configure_ai_gateway`가 반환한 `localEnv` 선택을 전달한다. 키 원문을 `env`나 도구 인자에 복사하지 않는다.

```json
{
  "file": ".env.apps-ai",
  "envKeys": ["LETSUR_BASE_URL", "LETSUR_MODEL"],
  "secretKeys": ["LETSUR_API_KEY"]
}
```

새 폴더로 checkout한 프로젝트에는 비밀 파일이 없을 수 있다. 이때 해당 폴더에서 `configure_ai_gateway`를 다시 호출한 뒤 검증한다. 기존 인계 기록에 파일명이 있다는 이유만으로 파일이 존재한다고 가정하지 않는다.

이 파일은 소스 압축에서 제외되고 API 키는 Apps 암호화 비밀값으로 전달된다. Git URL 배포에는 `localEnv`를 쓸 수 없으므로 로컬 checkout을 검증하고 배포하거나 기존 비밀값 설정 절차를 사용한다. 인계 기록에는 파일명, 변수 이름, 모델과 workspace만 남긴다.

Portal 키 변경은 이미 실행 중인 앱에 자동으로 적용되지 않는다. 최신 설정이 필요하면 `configure_ai_gateway`를 다시 호출한다. 기존 앱 반영은 사용자의 명시적인 설정 변경 또는 배포 요청 범위에서 수행한다.

## 디자인과 설명 스킬 연결

- 요청에 화면 제작이나 UI 개선이 포함되면 `../frontend-design/SKILL.md`를 읽고 해당 작업에 적용한다.
- 복잡한 구조를 그림으로 쉽게 설명해 달라는 요청에는 `../eli5/SKILL.md`를 사용한다.
- 배포만 요청한 경우 화면을 다시 디자인하지 않는다. 일반 진행 보고에는 설명용 HTML을 만들지 않는다.
