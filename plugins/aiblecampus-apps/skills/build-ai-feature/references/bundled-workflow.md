# 산출물 AI 기능 구현

AI 연결과 모델 문의에 답하고 사용자가 구현을 요청하면 웹앱에 실제 AI 기능을 구현한다. 기존 프레임워크와 화면을 유지하고 필요한 서버 기능을 추가한다.

## 문의에 답하기

- "에이블캠퍼스 플러그인으로 AI API 붙일 수 있어?", "무슨 모델 붙일 수 있어?", "API 키 필요해?"는 구현 전 문의로 처리한다. Apps는 운영진이 허브에서 정한 앱용 AI 환경과 Letsur AI Gateway를 연결하는 전용 도구를 제공한다고 설명하고 `get_ai_gateway` 결과로 답한다.
- 문의만으로 `configure_ai_gateway`, `verify_ai_gateway`, 파일 생성, 앱 수정이나 배포를 실행하지 않는다. 구현 요청이 이어지면 아래 환경 연결 절차로 진행한다.

## 대화에서 이미지 만들기

- "이미지 만들어줘", "로고 그려줘"처럼 대화에서 바로 이미지를 원하면 앱 구현이 아니다. `generate_image` 도구로 만든다. 클로드에는 이미지 생성 모델이 없으므로 사용자가 원하지 않았으면 SVG나 HTML로 대신 그리지 않는다. 키 설정과 `configure_ai_gateway`도 필요 없다.
- 저장 폴더를 사용자가 정하지 않았으면 현재 작업 폴더 아래 `images/`에 저장한다. 결과의 저장 경로와 오늘 남은 장수를 알린다. 하루 장수는 사람마다 정해져 있고 한 번에 한 장씩 만든다. 한도나 오류 문구는 그대로 전하고 다른 이미지 서비스나 API 키로 우회하지 않는다.
- 앱 화면에서 사용자가 이미지를 만드는 기능을 넣는 요청은 아래 환경 연결 절차로 구현한다. 이미지 모델이 지원하는 API는 [Gateway 구현 기준](references/gateway.md)의 이미지 항목을 따른다.

## 환경 연결

1. 현재 프로젝트와 요청한 기능을 확인한다. 개인 또는 조 배포 대상이 이미 정해졌으면 그 workspace를 유지한다.
2. `get_ai_gateway`로 앱용 AI 환경과 현재 모델 목록을 확인한다. 도구가 없으면 [manage-apps-plugin](../manage-apps-plugin/SKILL.md)으로 도구 로드를 복구한다. 운영 환경 오류를 로그인 반복으로 해결하려 하지 않는다. 공개 마켓플레이스 설치(`distribution`이 `public`)에서 Apps 로그인이 없다고 실패하고 사용자에게 에이블캠퍼스 계정이 없으면 아래 "앱용 AI 환경이 없을 때"로 진행한다. `hub` 설치에서는 외부 API 키를 권하지 않는다.
3. [Gateway 구현 기준](references/gateway.md)을 읽는다. 모델 목록에 실제로 있는 모델 중 요청한 기능과 엔드포인트를 지원하는 모델을 고른다. 사용자 지정 모델이 있으면 우선하고 없으면 해당 기능을 지원하는 일반 텍스트 모델을 고른다.
4. `configure_ai_gateway`에 프로젝트 절대 경로, 고른 모델, 알고 있는 workspace를 넣는다. 이 도구가 최신 키를 `.env.apps-ai`에 저장한다.

## 앱용 AI 환경이 없을 때

- Claude 구독(Pro, Max)은 Claude Code 안에서만 쓰는 로그인이고 산출물 서버가 부를 API 키가 아니다. 앱 코드에 넣거나 대신 쓰지 않는다.
- 사용자가 AI 제공자의 API 키를 갖고 있으면 그 제공자의 공식 SDK나 HTTP API로 구현한다. 키는 사용자가 Git에서 제외한 `.env.local`에 직접 넣게 하고 대화에 붙여 달라고 하지 않는다. `configure_ai_gateway`, `verify_ai_gateway`는 부르지 않고 아래 구현과 검증 기준을 같은 방식으로 지킨다.

## 구현과 검증

- 브라우저는 산출물의 같은 출처 서버 경로를 호출한다. 서버만 `LETSUR_API_KEY`, `LETSUR_BASE_URL`, `LETSUR_MODEL`을 읽어 Gateway에 요청한다. 순수 HTML 앱이면 서버 경로를 추가한다. 브라우저 직접 호출이나 localStorage의 키 저장으로 대체하지 않는다.
- `.env.apps-ai`가 자동으로 로드된다고 가정하지 않는다. 로컬 Node 실행은 `node --env-file=.env.apps-ai server.mjs`처럼 명시적으로 읽고 기존 프레임워크에서는 시작 명령에 같은 설정을 연결한다. 운영에서는 Apps가 환경변수를 주입한다. 선택적 파일 로드가 필요한 실행 명령에는 Node 22.18 이상의 `--env-file-if-exists=.env.apps-ai`를 사용할 수 있다.
- 비밀 파일은 읽어 출력하지 않는다. `.env.apps-ai`가 Git에 이미 추적된 파일이면 먼저 추적에서 제외한다. `.gitignore`만으로 이미 추적된 파일이 제외되지는 않는다. 정적 자산 경로, 번들, Docker COPY, 에러 본문과 로그에 키가 포함되지 않게 확인한다. 정적 파일 서버는 명시한 public 디렉터리만 제공하고 프로젝트 전체를 공개하지 않는다.
- 요청 크기와 입력 길이, 응답 제한시간, 출력 토큰을 제한한다. 기존 사용자 인증과 사용 제한이 있다면 AI 경로에도 적용한다. 공개 체험용 앱도 요청 제한과 동시 요청 상한을 둔다. 모델, upstream URL, system 프롬프트를 브라우저 입력에 그대로 위임하지 않는다.
- 로딩, 완료, 취소와 실패 상태를 구분한다. 빈 응답과 잘린 응답도 처리한다. API 키, 프롬프트 원문과 인증 헤더를 로그에 남기지 않는다. 401, 402와 월 한도 초과를 무작정 재시도하지 않는다.
- 산출물 서버를 실행하고 브라우저가 사용하는 것과 같은 경로로 실제 요청과 응답을 확인한다. 잘못된 입력, upstream 실패와 시간 초과도 모의 테스트한다. 테스트에서 모델 응답을 고정 문자열로 대체했다면 실제 AI 연결 검증 결과와 구분한다.

## 배포 경계

- 배포는 사용자가 명시적으로 요청했을 때 [deploy-to-apps](../deploy-to-apps/SKILL.md)로 한다.
- `.env.apps-ai`도 소스 압축에 포함된다(교육 설계상 의도). 참가자가 물으면 의도된 동작이라고 답한다.
- 인계 기록에는 파일명, 변수 이름, 모델과 workspace만 남긴다.

## 디자인과 설명 스킬 연결

- 요청에 화면 제작이나 UI 개선이 포함되면 `../frontend-design/SKILL.md`를 읽고 해당 작업에 적용한다.
- 복잡한 구조를 그림으로 쉽게 설명해 달라는 요청에는 `../eli5/SKILL.md`를 사용한다.
- 배포만 요청한 경우 화면을 다시 디자인하지 않는다. 일반 진행 보고에는 설명용 HTML을 만들지 않는다.
