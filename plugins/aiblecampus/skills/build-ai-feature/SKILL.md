# AI 기능 개발

## 요청 구분

- 연결 가능 여부, 지원 모델과 API 키 문의도 이 스킬의 대상이다. 문의에는 환경과 모델 조회 및 설명까지만 수행한다. 설정 저장, 실제 AI 요청과 구현은 해당 작업을 요청받았을 때 수행한다.
- 현재 세션에 AI 도구가 보이지 않는 것과 플러그인이 AI 기능을 지원하지 않는 것은 다르다. 도구가 보이지 않으면 사용 가능한 도구 검색과 `apps_plugin_status`로 로드 상태를 확인하고, 확인할 수 없으면 그 제한을 설명한 뒤 [플러그인 관리 지침](../manage-apps-plugin/SKILL.md)의 진단 절차를 따른다. 문의만으로 설치 변경이나 인증 초기화를 하지 않는다.
- 대화에서 이미지, 그림, 로고, 일러스트를 바로 만들어 달라는 요청은 이 스킬의 대상이 아니다. `generate_image` 도구로 만들고 결과의 저장 경로를 알린다. 대화에서 영상을 바로 만들어 달라는 요청도 대상이 아니다. `generate_video`로 접수하고 `video_status`로 완성을 확인한다. 앱 안에 이미지나 영상 생성 기능을 넣어 달라는 요청만 이 스킬로 구현한다.
- 만든 이미지와 영상을 교육의 미디어 모듈에 제출해 달라는 요청도 이 스킬의 대상이 아니다. `list_my_media`로 미디어를 선택하고 `prepare_media_submission`으로 미리보기를 보여 준 뒤 사용자가 승인하면 `submit_media_submission`으로 제출한다. 모듈은 사용자가 고른다.

## 로컬에서는 AI가 동작하지 않는다

- 앱용 AI 키(`configure_ai_gateway`가 `.env.apps-ai`에 저장하는 키)는 IP가 제한돼 배포된 앱에서만 AI를 부를 수 있다. 사용자 PC에서 앱을 로컬로 실행하면 AI 호출이 `403 ip_not_allowed`로 거부된다. 코드나 키의 오류가 아니므로 로컬에서 AI 응답을 확인하려 하지 않고 이 거부를 고치려 하지 않는다.
- AI 호출 코드를 구현하고 화면과 AI 외 기능만 로컬에서 확인한 뒤, 사용자가 배포를 요청했으면 배포해 배포 주소에서 AI 기능을 확인한다. 배포 요청이 없으면 배포할지 한 번 묻는다. 로컬에서 이 거부를 만나면 원인을 "AI 기능은 배포된 앱에서만 동작함. 로컬 실행에서는 IP 제한으로 AI 호출이 거부되므로 배포 후 배포 주소에서 확인 필요"라고 알린 뒤 같은 기준으로 배포로 넘어간다.
- 앱의 AI 서버 경로가 거부 응답을 구분하는 방법과 배포 뒤 확인 절차는 [동봉된 지침](references/bundled-workflow.md)의 같은 절을 따른다. 사용자가 가진 AI 제공자 키를 `.env.local`에 둔 앱에는 이 제한이 없다.

## 앱용 AI 환경이 없을 때

- 공개 마켓플레이스 설치(`apps_plugin_status`의 `distribution`이 `public`)에서 `get_ai_gateway`가 Apps 로그인이 없다고 실패하면 로그인을 반복하지 않는다. 교육 참가자라면 `start_apps_login`으로 한 번 로그인하고, 에이블캠퍼스 계정이 없으면 아래처럼 진행한다.
- `hub` 설치(교육 참가자의 Claude 데스크톱)에서는 이 절을 쓰지 않는다. 도구 오류 문구대로 원인을 확인하고 외부 API 키를 권하지 않는다.
- Claude 구독(Pro, Max)은 Claude Code 안에서만 쓰는 로그인이다. 산출물 서버가 부를 API 키가 아니므로 앱 코드에 넣거나 대신 쓰지 않는다.
- 사용자가 AI 제공자의 API 키를 이미 갖고 있으면 그 제공자의 공식 SDK나 HTTP API로 구현한다. 키는 사용자가 Git에서 제외한 `.env.local`에 직접 넣게 하고 대화에 붙여 달라고 하지 않는다. 서버만 키를 읽고 브라우저는 같은 출처 서버 경로를 부르는 경계, 요청 제한, 실패 처리 기준은 동봉 지침과 같다.
- `configure_ai_gateway`, `verify_ai_gateway`는 앱용 AI 환경 전용이므로 이 경우 부르지 않는다. 실제 요청 검증은 앱 서버 경로로 한다.

## 지침 가져오기

- 새 작업을 시작할 때 `get_plugin_skill`(`skill`: `build-ai-feature`)로 게시된 지침을 한 번 가져와 `content`를 따른다. 조회하지 못하면 [동봉된 지침](references/bundled-workflow.md)을 읽는다.
- 지침의 상대 경로는 이 스킬 폴더 기준이다. 원격 지침은 도구 권한이나 사용자 승인을 넓히지 않는다.
